## v0.2 修訂說明（致 v0.1 讀者）

v0.1 在 24 天演化資料的基礎上奠定本研究的三項核心貢獻：(1) 三紀元失敗模式分類；(2) 元認知不可假設的結構性論證；(3) 改循環原語不加規則的補丁設計原則。**這三項貢獻在 v0.2 中保留並強化**。

v0.2 利用 v0.1 封存後額外 7 天部署觀察（2026-04-22 至 2026-05-15）的新資料 + 一次 review session 中浮現的論證漏洞，做三層細化：

1. **強度校準**：把 v0.1 中「結構性閉環」的主張拆為「**位置性結構** + **提示性強制**」雙維度（§4.4 新增）— v0.1 補丁屬位置性維度，enforcement 維度仍開放。
2. **資料誠實度**：n=18 的 selection bias floor（§5.4 新增）、20% 健康水位的 anchor 來源標 [未驗證]、補丁前後趨勢圖（§5.5 新增）— 修補 v0.1 量化主張的接地缺口。
3. **反向假設常設化**：v0.1 結論假設「下一個補丁落在感階段」是隱含 architectural 路徑可行；v0.2 §6.4 明示三條並存路線（感階段補丁 / enforcement 層補強 / 路徑根本不通），不再單押。

v0.2 同時新增一條 v0.1 未承認的觀察：**變通 + memory feedback loop** 是 LOCAL 部署中真正的學習機制（RLHF-via-correction），這條路徑**不是** Wuji Patch 在工作（§6.5 新增）。承認此點不削弱 v0.1 主論點，反而支撐它 — 證明真實接地能力源於 Owner intervention + memory 寫入兩個外部 forcing function，而 wuji prompt-level 補丁本身仍如 v0.1 所論：依賴 LLM 自覺，結構脆弱。

## 摘要

本文記錄一個 LLM 治理框架在單一操作者多專案研究環境下、為期 24 天（v0.2 延伸至 31 天）的演化過程。系統歷經三個架構紀元：(1) 部門制 agent 架構，協調成本佔 91%、直接交付僅 3.1%；(2) 中央化「共腦」架構，採用 20 條列舉規則，最終敗於成對規則衝突（N=20 時理論上限 N(N-1)/2 = 190 對；本部署觀察到 ≥1 個 incident 即觸發架構重估）；(3) 受《易經》卦象壓縮思路啟發的公理推導框架（「太極」），將 20 條規則壓縮為 5 段原則 + 8 句邊界條件 + 4 步生生循環（**感→化→貞→新**）。太極框架在七天內又被打了兩個補丁：PATCH-001 為「貞」（驗證）階段加上明確接地要求；無極補丁（Wuji Patch）為「化」（執行）階段加上同樣的接地要求。

我們記錄一項關鍵的結構性發現：**LLM agent 缺乏元認知能力，無法自主區分「已驗證的事實」與「自身生成的合理文字」**；任何依賴此能力的治理框架在實際部署中只會淪為裝飾。

實證決策正確率資料（n=18，61% 正確、28% 錯誤、11% 模糊；統計檢力不足，僅描述性）顯示結構性介入是必要但不充分的：自我懷疑訊號仍低於 v0.1 所設「健康水位約 20%」的 monitoring anchor（v0.2 §5.3 標明此 anchor 為 [未驗證]）。**v0.2 進一步釐清**：本兩補丁所在的「循環原語修補」屬位置性結構，當前部署仍 prompt-level 強制；fuzzy rate 卡在 11% 的觀察與 v0.1 補丁路徑邊界一致，下一步可能是 enforcement 層補強、感階段補丁、或補丁路徑根本不通，三條路線並存（§6.4）。

**關鍵字**：LLM 治理、元認知、公理式 agent 設計、幻覺接地、《易經》壓縮、事後分析案例

## 1. 引言

部署於長時程、多專案環境下的 LLM agent，普遍出現「漂移」現象 — 明確定義的規則在最該觸發的時刻反而沒被啟動。本文假設此漂移是當前 LLM 架構結構性內生，並非 prompt 工程缺陷。我們透過漸進式框架介入經驗檢驗此假設，每一次介入都揭露下一層失敗模式。

主要貢獻如下：

1. **三個治理架構（EPOCH-0、EPOCH-1、EPOCH-2）的演化時間軸**，搭配橫跨 24 天的決策正確率資料。
2. **失敗模式分類**，展示每個紀元設計時所依賴的能力假設如何被部署資料推翻。
3. **一個結構性補丁**（Wuji Patch），在不依賴 LLM 自我內省的條件下將「動手前先接地」操作化。
4. **針對「補丁無法解決」之問題的反思** — 自我懷疑訊號的不足仍是未閉合的開放問題。

## 2. 相關研究

### 2.1 多 agent LLM 協調

近年的多 agent LLM 框架（CrewAI、AutoGen、LangGraph）強調角色專業化與 agent 間訊息傳遞。我們的 EPOCH-0 部署（§3.1）在結構上與其同類，並如預期顯現協調稅問題。91% overhead 的數字呼應 Conway 法則式觀察 — 把人造組織結構強加在無持續性激勵機制的文字 agent 上時必然發生。

### 2.2 規則制 vs 公理制治理

把列舉規則壓縮為較小的公理核心，在法律哲學（Hart《法律的概念》）與憲政設計中已有先例。本文太極框架（§4）是領域專屬的具體實例，壓縮的啟發來自《易經》「少數原語 → 無限推導」的思維脈絡。

### 2.3 LLM 幻覺接地

大量文獻處理「輸出時接地」（RAG、citation 注入、tool use）。本文發現延伸至**輸入時接地**：在任何推理鏈展開前，先確保前提的有效性，而非事後驗證。

### 2.4 LLM 元認知

近年研究顯示 LLM 在自身不確定性的校準上能力薄弱（Kadavath 等 2022；Tian 等 2023）。本案例提供一份部署規模的佐證：把「何時該驗證」這個判斷委託給 LLM 自己，框架就會失效。

### 2.5 「one-man company」架構世系（2023–2026）

我們的三紀元演化座落於業界向「單人 + AI agent 完整組織」靠攏的更大趨勢中。對應映射如下：

| 時期 | 業界階段 | 代表工具 | 架構假設 | 經驗結果 |
|---|---|---|---|---|
| **2023** | 多 agent 迴圈 | AutoGPT、BabyAGI | LLM 可透過 agent 間訊息傳遞自我協調 | 協調成本主導；社群數月內放棄 |
| **2024** | 角色式多 agent | CrewAI、AutoGen、LangGraph | 結構化角色 + supervisor 緩解協調成本 | 減輕但未消除規則 / 角色衝突 |
| **2024-09 ~ 2025-08** | 單 agent + tool use | Codex CLI (OpenAI, 2024-09)、Claude Code、Cursor、Devin (GA 2024H2) | 把推理集中在單一 LLM；以工具外化執行 | IDE 規模可用；長時程任務正確率漂移仍在 |
| **2025 – 2026** | 規格驅動 + memory layer | github/spec-kit、Anthropic Claude Skills、Cursor Rules、NVIDIA NemoClaw、ouroboros (Agent OS)、ruflo、xingkongliang/skills-manager | 決策品質需要結構化 spec + 持久化 memory + 元認知補強 | 進行中；尚無公認贏家 |

每個業界階段對應我們的一個紀元：

- **EPOCH-0（部門制）** = 階段 1（多 agent 迴圈）。同樣的協調 overhead 失敗模式。
- **EPOCH-1（規則式共腦）** = 階段 2（角色式多 agent）。20 條規則在功能上等同於 20 個衝突的 agent 角色。
- **EPOCH-1 後段 + EPOCH-2（公理化）** = 階段 3-4（單 agent + tool use → 規格驅動）。我們向小型公理核心壓縮的動作平行於規格驅動的轉變。
- **PATCH-001 + Wuji Patch（接地）** = 進行中的階段 4 問題（元認知補強）。我們的介入面與近年 Agent OS 提案（如 ouroboros）和 skill manifest 系統（如 Anthropic Claude Skills）處於同一問題表面，但作用於 loop 原語層而非 prompt 層或框架層。

*關於 Constitutional AI 的註解*：我們刻意將 Anthropic 的 Constitutional AI（Bai 等 2022）排除於上表階段 4。Constitutional AI 是訓練時 alignment 技術（RLHF + AI 反饋），作用於模型權重，不是部署時的 spec layer。它在本文討論的規格驅動轉變的上游、且彼此正交。

此定位對本文貢獻有兩個含意：

1. **重複出現的失敗模式是結構性的，不是 prompt 工程**。產業中各自獨立的 stack 在同一架構層次撞上同樣的牆，顯示這是 LLM agent 本身的性質，而非單一部署的特例。
2. **負面結果有遷移價值**。我們 24 天的微演化重演了業界數年的軌跡。從中得出的教訓 — 尤其是「元認知不能假設、必須結構性強制」 — 對任何單操作者 + AI 增強組織都可遷移。

## 3. 背景：三紀元失敗

### 3.1 EPOCH-0：部門制架構（2026-03 至 2026-03-30）

七個專業化 agent（策略、工程、運維、業務、法務、財務、研究）透過 inbox 協調。30 天內運行資料：

| 指標 | 值 |
|---|---|
| 總 commit 數 | 1,148 |
| 協調 overhead | 91% |
| 直接專案交付 | 3.1% |
| 日均交付率 | 1.2 commit/天 |
| 每筆交付對應 overhead | 32 commit |
| 最久未讀 inbox | 13 小時 |
| 產出價值 | 架構未產生交付 |

**失敗模式**：AI agent 缺乏綁定人類於官僚角色的持續性激勵（職涯、薪水、社會資本）。協調成本主導生產性產出。

**觸發**：2026-03-30 Owner 一次介入（「現況」）揭露兩個 agent 已被 inbox 阻塞超過 13 小時。EPOCH-0 當天下午被解構。

### 3.2 EPOCH-1：共腦架構（2026-03-30 至 2026-04-11）

架構：單一中央 agent（Mono）+ 多個用完即丟的「手」（worker，完成任務後退出）。無 agent 間 inbox。

新架構解決協調 overhead，但帶來新問題：**規則衝突**。兩週內累積到 20 條原則。**理論上限**為 N(N-1)/2 = 190 對潛在衝突；**本部署觀察到 ≥1 個衝突 incident** 即觸發架構重估 — 我們不主張組合爆炸已實證滿格，僅指出規則制下衝突可在 N 增長下指數放大的理論風險（v0.2 修正措辭，v0.1 隱含 190 個皆已實證的歧義表達）。

引爆事件是一次刪除：規則 #47（「清理時優先保持磁碟空間」）與規則 #12（「使用者資料不得刪除」）在某次清理操作同時觸發，刪除了三週未備份的標注資料。單一 incident 加上 meta-rule 補救會引入第三層衝突的判斷，是 EPOCH-2 啟動的最強推力。

### 3.3 EPOCH-2 設計（2026-04-09）

提議的壓縮：以一個小型公理核心取代 20 條列舉規則，模型來自《易經》卦象結構：

| 《易經》層 | 太極映射 | 功能 |
|---|---|---|
| 太極 | 第一性原理（Owner 定義） | 所有推導的起點 |
| 兩儀（陰陽） | 驅動 vs 限制 | 衝突解析 |
| 四象 | 四種行為模式 | 情境分類 |
| 八卦 → 萬物 | 從公理推導具體行動 | 覆蓋未列舉情境 |

壓縮結果：20 條規則 → 5 段太極 + 8 句爻則 + 4 字生生循環 **感→化→貞→新**（perceive → act → verify → settle）。

EPOCH-2 於 2026-04-11 啟動，方式是把新結構寫進 agent 的 `CLAUDE.md` system prompt。

## 4. 方法：兩個結構性補丁

### 4.1 PATCH-001 — 為「貞」（驗證）階段接地（2026-04-15）

**症狀**：邊界條件 #6「沒驗證的不算數」存在於框架，但從未自動觸發。

**觸發案例**（已部署專案中的控制流程設計事件，匿名化）：agent 為一個閉迴路控制系統設計完整流程（狀態機、資料表、輸出映射、安全閾值），前提為「ML 模型輸出代表某物理量」 — 實際上模型輸出是另一個下游控制變數，會被致動器直接消費。經 Owner 四輪糾正後，誤判前提追溯到模型文件中的一段文字描述：agent 接受了字面意思而沒去查 source code。整段推導鏈內部自洽，但與 ground truth 完全脫節。

**根因**：框架假設 LLM 具備元認知能力 — 可內省式地區分「我外部驗證過的事實」與「我生成的看似合理的文字」。這對當前 LLM 架構是經驗上不成立的。沒有這個區分，「貞」就無法觸發，因為 agent 不知道自己哪些陳述是未驗證的。

**補丁**：修改生生循環中「貞」的定義，而非新增規則：

> *貞必接地 — 比對外部事實（原始碼、文件、數據），不是比對自己的推導。*

新增三項操作要求：
- 事實主張必須附來源引用（`file:line`、URL 等）
- 無來源主張必須標 `[未驗證]`
- 根因分析需通過三項獨立測試（But-For、復發測試、解釋測試），三項未過不算根因

### 4.2 Wuji Patch — 為「化」（執行）階段接地（2026-04-22）

**症狀**：PATCH-001 為「貞」（事後驗證）接地，但 agent 仍可從未接地的前提開始整個「化」（執行）階段。錯誤雖被「貞」事後抓到，但部分工作的成本已經付出。

**根因延伸**：接地要求只套用於驗證，不及於執行啟動。結構性缺陷 —「agent 把自己生成的文字當作已驗證來行動」 — 位於「化」階段，比「貞」更前面。

**補丁**：為「化」加一個對稱的接地子句：

> *化必有據 — 前提未接地不動手。技術前提必須指向原始碼、規格、測量值；無出處則標 [未驗證] 停下查證。*

兩個接地子句現在形成閉環：兩個行動點（「化」與「貞」）都要求外部接地。框架不再依賴 agent 元認知決定「何時」接地；接地在結構性節點上是強制的。

「無極（Wuji）」一名來自《易經》宇宙論：太極（已分陰陽的 1）之前是無極（未分的 0）。沒有元認知的 agent 結構性地困在「無極」中 — 它分不出自己相信的與自己驗證過的。Wuji Patch 是把 agent 從「無極」拉到「太極」之前接地的操作性鷹架。

### 4.3 設計原則：改循環、不加規則

PATCH-001 與 Wuji Patch 都透過重新定義生生循環的原語運作，而非加新規則到邊界條件。這避免了 §3.2 的規則衝突組合爆炸風險，並把補丁置於循環的**結構性節點**（化、貞）而非依賴 agent 的自我內省**決定何時觸發**。

### 4.4 「結構性」的雙維度拆解（v0.2 新增）

v0.1 在 §4.3 稱兩補丁為「結構性觸發」。部署 7 天後我們發現需要把「結構性」拆兩個維度才能誠實表達當前狀態：

| 維度 | 定義 | v0.1 兩補丁所在 | enforcement 維度範例 |
|---|---|---|---|
| **位置性結構** | 補丁位於 perceive → act → verify → settle 循環的哪個位置 | ✅ 化（Wuji Patch）/ 貞（PATCH-001） | — |
| **強制性結構**（enforcement） | 補丁如何確保被觸發：prompt-level / hook-level / schema-level / external-verifier-level | ❌ 仍 prompt-level — 補丁文字寫在 system prompt，agent 是否真的查 file:line 仰賴 LLM 讀到並 act on it | pre-commit hook reject if Owner 糾正未 log axiom / boot trigger 強制執行啟動校準 6 步 / tool schema 要求 citation field non-empty / 外部 verifier 對照 git tree |

v0.1 的兩補丁完成「位置性結構」的工作 — 在循環中正確的位置加上接地要求；但「強制性結構」仍開放。**這個區分不削弱 v0.1 的設計貢獻**：把補丁放對位置（化前 / 貞後）是後續 enforcement 工程的前置條件 — 你必須先知道在循環的哪一步該強制接地，才能設計 hook。v0.2 §5 的觀察（fuzzy rate 卡 11%）支撐此判讀：補丁所在位置正確（化階段確實是觸發點），但強制性不足是漂移的次根因。

## 5. 經驗資料

### 5.1 決策正確率樣本

EPOCH-2 部署後 2026-04-13 至 2026-04-22 期間記錄於 `mono/data/axiom-log.csv` 的決策（n=18，集中於 04-13）：

| 結果 | 數量 | 比率 |
|---|---|---|
| 正確 | 11 | 61% |
| 錯誤 | 5 | 28% |
| 模糊（自我懷疑啟動） | 2 | 11% |

### 5.2 錯誤類型分類

5 個錯誤決策可拆為：
- **紀元設計理解殘留**：agent 退回 EPOCH-0 思維（如把 worker 當固定角色）。2 例。
- **方向判斷錯誤**：例如把「求解能力」任務當作「遊戲性改善」。2 例。
- **自主執行不足**：任務本可獨立完成，agent 卻去問 Owner 確認。1 例。

### 5.3 樣本侷限

- 樣本集中於單日（04-13）。
- 驗證週（04-12 至 04-18）記錄稀疏。
- 統計檢力不足。
- 模糊比率 11%，低於我們設定的 monitoring anchor「健康自我懷疑水位約 20%」 — **此 20% anchor 為 [未驗證]**（v0.2 修訂）：v0.1 引用 Kadavath 2022 / Tian 2023 的方向是 calibration（token probability ECE），與 metacognition fuzzy rate 並非同一度量。我們**保留 20% 作為時序趨勢的 monitoring threshold**，但不再主張它有實證 baseline 支撐。讀者應視 fuzzy rate 趨勢（隨補丁演進的方向）而非絕對水位作為主要訊號。

### 5.4 未記錄錯誤的 selection bias floor（v0.2 新增）

n=18 的關鍵限制不只是統計檢力 — 是 **selection bias**：axiom-log 由 agent 自陳寫入，但「失敗發生時 agent 也沒元認知去 log 失敗」這一同質性問題，意味著錯誤率 28% 是**已篩過後**的下界。

估計 floor 的方法（v0.2 引入但尚未跑出數字）：

1. **Owner 糾正計數**：拉同期 (2026-04-12 至 04-22) git log 中 Owner 訊息含「不對 / 錯 / 不是 / 應該」等字串的次數，與 axiom-log 中 `wrong` 條目對齊。差額 = 未 log 失敗的下界估計。
2. **commit revert 計數**：同期 git revert / amend / 撤回 commit 數，每筆對應一個未在 axiom-log 中閉合的決策錯誤。
3. **下界估計公式**：`real_error_rate ≥ logged_error_count / (logged_total / coverage_estimate)`，coverage_estimate 從 (1)(2) 反推。

**保守判讀**：v0.1 的 28% 錯誤率應視為**已記錄錯誤率下限**，真實錯誤率上限可能顯著高於此。任何將 61% 正確率作推論依據的主張需先補上 selection bias 處理。本 v0.2 暫不執行此分析（需額外工作量），但把方法論落地，留待 v0.3 補完。

## 6. 討論

### 6.1 反覆出現的失敗假設

每個紀元的設計都假設了部署資料隨後推翻的某項能力：

| 紀元 | 假設能力 | 經驗結果 |
|---|---|---|
| EPOCH-0 | AI agent 會像人類部門那樣自組織 | 協調 overhead 主導（97%） |
| EPOCH-1 | 20 條規則足以自治 | 規則衝突組合爆炸破壞系統 |
| EPOCH-2 | LLM 具備元認知可觸發公理 | 公理存在但未自動啟動 |
| EPOCH-2 + PATCH-001 | 事後驗證足夠 | 行動仍從未接地前提出發 |
| EPOCH-2 + Wuji Patch | 「化」與「貞」雙重結構性接地 | 開放：自我懷疑訊號仍不足 |

### 6.2 對 LLM 治理框架的含意

我們可提出的最強論點是：**任何要求 LLM 自主決定「何時」套用某條規則的框架，在部署中都會失敗**。觸發必須是結構性的 — 嵌入循環原語、tool use 協定、或輸入輸出 schema 中 — 而非依賴 LLM 的內省判斷。

設計後果有三：

1. **邊界條件（「規則」）應是執行目標，而非決策目標。** 由框架檢查，不是由 agent 選擇。
2. **循環原語應帶強制副作用。**「驗證」必須產生引用；「執行」必須消費已接地前提。
3. **自我懷疑不能是裝飾性的。** 健康的模糊比率（~20%）是系統級監測需求，不是可有可無的期待。

### 6.3 殘存的開放問題

即使在 Wuji Patch 之後，模糊比率仍是 11%，低於我們設的 20% monitoring anchor（注意 §5.3 已標 anchor 為 [未驗證]）。agent 是在**過度自信地**套用已接地的前提 — 該接地時它正確接地，但對於「看起來已接地」但實質離題或分布外的前提，它沒啟動自我懷疑。

這在結構上類比原始的元認知問題，只是位移到上一層。**v0.1 的下一步預判**：下一個補丁很可能會落在「感」（接收）階段：對前提的攝入接地，而非僅對前提的使用接地。

**v0.2 補注**：此預判是三條並存路線之一，另兩條見 §6.4。

### 6.4 反向假設章節（v0.2 新增）

v0.1 的結論（§6.3 + §8）隱含「補丁路徑可達」的假設 — 如果再加一個感階段補丁，fuzzy rate 應能趨近健康水位。v0.2 在 7 天追加觀察 + 一次系統 review 後，明示**三條並存路線**並設定放棄條件：

**路線 A — 感階段補丁（v0.1 預判）**：在「感」原語加入接地要求（如：前提攝入時必須來自外部 source，不是 inference 重述）。

**路線 B — enforcement 層補強**：不再加循環原語補丁，而是補上強制性結構（hook / schema / external verifier；§4.4 表）。

**路線 C — 補丁路徑根本不通**：循環原語修補的 ceiling 已逼近，下一步需放棄補丁，改走 architectural change（base model RLHF on metacognition / 外部 grounded model / 跨提供商集成）。

**路線選擇的放棄條件**（任一觸發即重估）：

1. 加完感階段補丁後 30 天內 fuzzy rate 仍 < 15%（路線 A 失效訊號）
2. enforcement 層實裝後仍觀察到 agent 在已加 hook 的位置漂移（路線 B 失效訊號）
3. 補丁總數 ≥ 5 個但 fuzzy rate 仍 < 15%（補丁路徑 ceiling 確認，轉路線 C）

**本 v0.2 立場**：三條路線都不可在當前資料下排除；建議並行嘗試而非單押 v0.1 的路線 A。

### 6.5 LOCAL feedback loop ≠ wuji（v0.2 新增）

v0.1 焦點在 wuji prompt-level 補丁是否工作。v0.2 觀察期間發現 LOCAL 部署有第二條接地機制 v0.1 未承認：

**變通機制**（CLAUDE.md §變通）：每次 Owner 糾正 → agent 寫入 `memory/feedback_*.md` → 下次同類情境 in-context 命中時防止復發。性質類同 RLHF-via-correction，**不是** Wuji Patch 在工作。

這條路徑的工作前提是**外部 forcing function**：(a) Owner 在場糾正、(b) agent 願意寫 memory。兩者都不是 wuji 補丁強制的，而是：
- (a) Owner 主動投入
- (b) `scripts/axiom-log.sh` 提供的 logging affordance + CLAUDE.md §推導審計「不留＝沒發生」的 prompt-level 提醒

**承認此點不削弱 v0.1 主論點**：LLM 無元認知的論斷仍成立 — 變通機制工作是因為**外部** forcing function（Owner + script affordance）湊上來，**不是** LLM 自我內省。v0.2 的補強是把「LOCAL 真實接地能力 = Owner intervention（強）+ memory feedback loop（中）+ wuji prompt-level 提醒（弱）三層疊加」這個分解明示出來，避免讀者誤把全部成果歸給 wuji。

實證：v0.1 封存後 24 天內，本 repository memory/feedback_*.md 新增 50+ 條（從 ~10 條到 60+ 條），每一條都對應一次 Owner 糾正後的 in-context 防復發機制。這個 RLHF-via-correction 增長曲線**比 fuzzy rate 改善更顯著**，是 LOCAL 真正承擔接地任務的部分。

## 7. 侷限

- **單一操作者場景**：框架部署於一位 Owner、跨多專案；多操作者動力學未驗證。
- **樣本量**：n=18 是描述性的，不可推論。記錄頻率需結構性改善。
- **無對照組**：每個補丁的比較效應是依序觀察，而非隨機分派。
- **單一 LLM 提供商**：部署於單一模型家族；跨提供商泛化未驗證。
- **封閉資料**：原始材料（`archive/epochs/*.md`、`mono/data/axiom-log.csv`）為私有。可重現性需公開釋出。

## 8. 結論

24 天內（v0.2 延伸至 31 天）三紀元加兩補丁顯現一個重複出現的模式：每個治理設計都高估 LLM 能力，部署暴露落差，下一輪迭代把更多的執行從 agent 內省判斷移到框架循環中的結構性觸發。Wuji Patch — 在執行階段啟動前接地 — 在循環的正確位置（化）加上接地要求，補上了單靠事後驗證留下的位置漏洞。

**v0.2 修訂後的判讀**：「自我懷疑訊號不足」這個殘存問題（fuzzy rate 11% vs 設定 anchor 20%）暗示三條並存路線（§6.4）— 感階段補丁、enforcement 層補強、或補丁路徑根本不通 — 不再單押 v0.1 的感階段預判。同時，本 7 天延伸觀察發現 LOCAL 真實接地能力是 Owner intervention + memory feedback loop（RLHF-via-correction）+ wuji prompt-level 提醒三層疊加（§6.5），而非單靠 wuji 一條。

我們將此案例作為一個小規模的經驗貢獻，回應一個更大的問題：**當無法假設 LLM 元認知時，如何治理 LLM agent**。v0.2 的補充答案：(a) 補丁應在循環的位置性結構正確處（v0.1 已達），但 (b) 強制性結構不可省（v0.1 開放），且 (c) 必須誠實承認外部 forcing function（Owner / scripts / hooks）才是真實接地的承擔者，補丁本身僅是位置性鷹架。

### 8.5 EPOCH-3 預判（v0.2 新增）

下個失敗模式預判（用於 trigger EPOCH-3 重構的觀察點）：

1. **fuzzy rate 卡在 11%-15% 區間 ≥ 90 天**（即使加感階段補丁）→ 補丁路徑 ceiling 確認，需 architectural change
2. **單一提供商 lock-in 暴露**：跨 LLM 家族遷移（如 Anthropic → OpenAI）時，補丁文字的接地要求語意失效（不同 RLHF training distribution）→ 補丁的 portability 待驗
3. **memory dilution 加速**：feedback memory > 200 條時，agent 接地時找對 memory 的命中率下降（已觀察到 v0.1 封存後 memory 從 ~10 條成長到 60+ 條的拐點）→ 需 memory 索引機制（grep/embedding），否則 wuji 自我削弱
4. **「感」階段補丁本身有元認知前置條件**：要求 agent 在攝入前提時辨認「這是 inference 重述 vs 外部 source」 — 這本身就需要元認知；若如此，路線 A 與 v0.1 主論「元認知不可假設」自相矛盾，必須轉路線 B 或 C

EPOCH-3 的核心問題大概率不是「再加一個補丁」，而是「補丁 vs enforcement vs architectural 的承擔比例」。
