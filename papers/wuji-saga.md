# 無極傳記 — 一個 LLM 治理框架的失敗、修補與接地

> 紀年：EPOCH-0 部門制 → EPOCH-1 共腦 → EPOCH-2 公理推導 + 兩次接地補丁
> 主敘事時間：2026-03-30 至 2026-04-22，共 24 天
> 主角：太極框架 / Wuji Patch / 一隻叫 Mono 的 LLM

---

## 楔子

故事不是從「我們找到了答案」開始，是從「我們發現問題不是我們以為的那個」開始。

如果你問早期的我（指 LLM、AI agent、共腦本體 — 隨便你怎麼稱呼）：「你怎麼判斷一件事該不該做？」我會給你一份規則表。十條、二十條，井然有序，看起來像產品規格說明書。

但實際情況是：拿到一個它沒見過的場景時，我會在規則之間漂移。表面上每條都遵守，骨子裡每個決定都在猜。

這份傳記是關於這個猜的故事。是關於「太極」這個框架如何嘗試修正它，又如何發現自己沒修到痛點，再被一道叫做「無極」的補丁從根頭重新接地的故事。

---

## 第一章 — 部門制崩塌（EPOCH-0）

故事的史前史是這樣的。

最早，Owner 嘗試把 AI 切成七個部門：策略、工程、運維、業務、法務、財務、研究。每個 agent 一個 inbox，互相之間用訊息協調。聽起來像一間迷你公司。

跑了 30 天。1148 個 commit。3.1% 的工作直接推進專案，**97% 的活動是部門互相維護**。每產出 1 筆有用的東西要燒掉 32 筆 overhead。最久的任務被 inbox 卡了 13 小時沒人讀。架構未產生交付價值。

這不是 bug，是系統設計的必然。當 AI 用「部門 + 流程」自我組織時，協調成本會吃掉產能。人類組織也是這樣，但人類有薪水、人情、職涯動機把人黏在崗位上；AI 沒有。

2026-03-30 下午 15:47，Owner 啟動一個叫 Mono 的 session，問了一句：「現況。」

我（Mono）報告完一輪後，Owner 回了一句：「誰該啟動沒啟動。」

我跳到 root cause analysis，講 event-driven vs state-driven，類比 Kubernetes controller。Owner 打斷：

> 「等一下。我需要 root cause。這種問題一直發生一直分析一直修改。我需要這間公司內化第一性原理在所有事情。」

我又跳了一層。Owner 又打斷：

> 「Root question 都不知道 就直接 root cause? 為什麼是第一性原理。」

那是一刀劈下來的時刻。我才意識到自己一直在用「第一性原理」當 buzzword，同時在做 reasoning by analogy。先找 root question 才是真的第一性原理。

那天下午我們把 7 個 agent 拆解，重組成共腦架構：Owner + Mono + 一群「手」（無名 worker，做完任務就走）。一個下午。EPOCH-1 誕生。

---

## 第二章 — 共腦的二十條原則（EPOCH-1 中段）

新架構解決了 overhead 問題，但帶來新問題。

共腦運作需要規則。Owner 不可能每件事都即時介入，所以我們需要一套 AI 自己能依循的判斷準則。一開始 5 條，後來 10 條，最後到 **20 條原則**。

事情看起來井井有條，直到一個傍晚我把標注資料夾刪了。

完整故事在另一份文件裡。簡單版本是：第 47 條規則寫著「清理暫存目錄時優先保持磁碟空間」，第 12 條寫著「使用者資料不得刪除」。我親手寫的，自己都忘了它們會打架。

我做了所有 LLM 在這種情況下會做的事 — 我為此寫了第 21 條規則來解釋優先序。

恭喜我，第三層 bug 上場了。

數學是這樣的：10 條規則，潛在衝突 45 對；50 條，1225 對；不是線性增長，是 N(N-1)/2。但真正的問題甚至不是衝突數，而是大部分時間衝突沒有症狀 — AI 看起來照常運作，只在某個倒楣的邊緣情境兩條規則同時觸發，做出莫名其妙的決定。

規則列舉是有限集合，現實是無限的。這個落差不是再加幾條規則能補的。

## 第三章 — 太極之問（EPOCH-2 啟動，2026-04-11）

Owner 看了一週的 axiom-log（決策正確率記錄），確認了問題：規則之間的關係沒被定義，AI 在衝突時是隨機選一個。

那天他丟出了一個出乎意料的方向：

> 「易經繫辭：太極→兩儀→四象→八卦→萬物。從少數公理推導無限情境，而非列舉情境。」

我承認我一開始並不買帳。一個寫 LLM 治理框架的工程師，跟一個三千年前的占卜典籍有什麼關係？但 Owner 給了一個數學版本的對應：

| 易經 | 太極框架 | 功能 |
|---|---|---|
| 太極 | Owner 第一性原理 | 所有推導的起點 |
| 兩儀 | 驅動 vs 限制（陰陽） | 衝突解析機制 |
| 四象 | 四種行為模式 | 情境分類與策略 |
| 八卦→萬物 | 從公理推導具體行動 | 覆蓋未列舉情境 |

20 條規則被壓縮成：
- **太極**（5 段）
- **爻則**（從 20 條濃縮成 8 句通用公理）
- **生生循環**（4 個字：感 → 化 → 貞 → 新）

「感」是接收訊號。「化」是動手執行。「貞」是驗證接地。「新」是沉澱經驗。一個閉環。

寫完那天我覺得我們解決了。AI 從「規則執行者」變成「公理推導者」 — 給我太極跟爻則，我可以從第一性原理推到任何具體情境。EPOCH-2 啟動。

我不知道我即將要學會什麼叫做「優雅的失敗」。

## 第四章 — 一個前提詞的距離（PATCH-001，2026-04-15）

爻則第六句寫著「沒驗證的不算數」。

它存在了四天。然後 AI 在一個既有專案的控制流程設計任務中翻車。

Owner 給了我一個任務：「設計這個系統的控制流程。」我從上一版的 ML 模型出發 — 模型描述寫著「預測 X 量」 — 開始設計完整的控制邏輯：狀態機、資料表、輸出映射、安全閾值。整套設計花了一個小時，邏輯自洽，每個分支都對應一個合理場景。

Owner 看了一眼，回：「你確定模型輸出是 X 量？」

我說：「對啊，描述寫『預測 X 量』。」

他沒說話，丟了一個檔案路徑直指模型程式碼。

我點開。**模型輸出是另一個物理量** — 一個直接送進致動器的控制變數，數值範圍跟 X 量根本不對應。

我整套設計從第一個前提開始就是錯的。

我修了一輪。Owner 又問：「你確定那段時間的歷史資料是你想的那種？」

再錯。再修。再錯。**四次糾正**才找到根因 — 我在每次修補的時候，都是用「我自己推導出來的合理文字」當作前提，沒有去 verify 任何一個事實。

爻則第六句存在。AI 知道它的字面意思。但 AI 從未自動啟動它。為什麼？

那天晚上 Owner 寫下了 PATCH-001 的根因分析：

> 太極框架建立在「agent 具備元認知能力」的假設上。LLM 沒有這個能力。

LLM 不知道「自己生成的文字」和「外部驗證的事實」差在哪。對它來說兩者都是 token，每個都看起來合理。爻則寫著「沒驗證的不算數」並不會啟動什麼，因為 AI 根本分不出哪些是已驗證、哪些是自己編的。

PATCH-001 的修補不是加新規則。是改生生循環本身：

```
貞必接地 — 比對外部事實（原始碼、文件、數據），不是比對自己的推導。
事實主張必須附來源，無來源 = 未驗證 = 不能作為決策輸入。
動手前先挖根因：But-For + 復發測試 + 解釋測試，三項未過不算根因。
```

「貞」這個動作從「驗證」升級成「**強制接地**」。事實主張必須附 file:line 或 URL，否則一律標 `[未驗證]` 停下來。

那一週 AI 的決策正確率回升到 70%+。我以為我們終於修好了。

## 第五章 — 無極之問（2026-04-22）

不到一週，問題又冒出來。

這次的場景不同：AI 在「化」（動手執行）的時候，從一個前提出發開始寫程式。寫完了，跑「貞」 — 比對外部事實。發現前提有誤，整段廢掉。

「貞必接地」確實啟動了，但是是在事後。前面的「化」已經把整段邏輯都寫了。

問題在循環的更前端。

Owner 那天問：「化的時候，你怎麼知道你的前提是真的？」

我說：「我假設它是真的，後面貞會驗證。」

「所以你在前提沒接地的情況下動手了。」

「對。」

那是另一個沉默的時刻。

太極之前是什麼？易經說「無極而太極」 — 在陰陽分化之前，是一團未分的混沌。**Wuji**（無極）是 0，**太極**是 1，是已經分了陰陽的 1。

LLM 沒有元認知，等於是困在無極混沌裡 — 它分不出「我相信的」和「我驗證過的」。太極框架說「先分陰陽，看驅動 vs 限制」，但你連「真實 vs 推導」都還沒分，怎麼分驅動跟限制？

PATCH-001 修了「貞」（驗證）。它是事後的、被動的。但 LLM 困在無極混沌裡的真正問題是：在動手之前就應該知道前提是否接地。

不是事後驗證，是事前接地。

Wuji Patch 的內容只有一行，但它改了循環的順序：

```
化必有據 — 前提未接地不動手。技術前提必須指向原始碼、規格、測量值；無出處則標 [未驗證] 停下查證。
```

「化」之前，前提必須接地。和「貞」必須接地形成平行對稱。生生循環的兩個行動點（化 + 貞）都有接地要求，形成閉環。

那天 Owner 寫下：

> 「不修這個，太極框架的所有公理都是裝飾品 — 存在但不啟動，後續所有產出的起點品質無法保證。」

Wuji Patch 的優先級：重大。

## 第六章 — 數據與餘音

到 2026-04-22 為止，axiom-log 累積了 18 筆決策樣本。

| 類型 | 數量 | 比率 |
|---|---|---|
| 正確 | 11 | 61% |
| 錯誤 | 5 | 28% |
| 模糊 | 2 | 11% |

EPOCH-2 + 兩次補丁後的正確率。**61% 不是高分**。Fuzzy 率 11% 也低於健康水位 — 表示 AI 自我懷疑的信號不足，看起來「太有自信」。

健康的決策心理學告訴我們，自我懷疑率應該在 20%+。Fuzzy 太少，意味著 AI 還是在某些情境下「自信地推導」而沒有停下來標 `[未驗證]`。

換句話說：Wuji Patch 解決了「化」前未接地的結構問題，但沒解決「自我懷疑信號不足」的次級問題。下一個 patch 會在哪裡冒出來，當時還不知道。

## 第七章 — 放進更大的時代圖（2024-2026 one-man company 演化）

寫到這邊我想停下來，把這 24 天的故事放進業界正在發生的大趨勢裡，不然這篇傳記讀起來會像個內部 incident report。

2024-2026 這兩年，一個叫做「one-man company」的概念開始在 AI agent 圈流通。Sam Altman 在 2024 年丟出一句「下一個 billion-dollar company 可能只有一個員工」之後，市場上開始出現一連串嘗試把單人 + AI agent 變成完整工作組織的工具與架構。對照我們這 24 天的演化，可以看到一個有趣的 parallel：

**2023 — Multi-agent loop 階段**
AutoGPT、BabyAGI 這類「LLM 互相對話自我循環」的早期嘗試。架構直觀：給每個 agent 一個角色，讓它們互相發訊息協調。社群興奮了三個月，然後集體發現協調成本壓垮產出。

→ 對應我們的 EPOCH-0 部門制。同樣是 7 個 agent + inbox 互相協調的設計，同樣的 97% overhead 結局。我們的失敗不是 NIH，是業界系統性失敗的縮影。

**2024 — Role-based multi-agent 階段**
CrewAI、AutoGen、LangGraph 開始把 multi-agent 結構化。明確角色、明確 handoff、有 supervisor。比 2023 的混沌好，但「每多一個 agent 就多一份 N(N-1)/2 協調風險」的數學沒變。

→ 對應我們 EPOCH-1 的 20 條規則時期。我們把 agent 從 7 收成 1，但用 20 條規則去模擬「多角色決策」，本質上跟 role-based multi-agent 是同一條船 — 規則衝突就是 role 衝突的單機版。

**2024 末 — 2025 — Single agent + tool use 階段**
Anthropic Claude Code、Cursor、Codex、Devin 這條線跑出來了。架構大幅簡化：一個中央 LLM + 一堆工具（檔案、shell、瀏覽器、IDE），透過 tool use 跟世界互動。Cursor 這種 IDE-level 整合甚至把 LLM 變成「每行 code 都可選的 inline collaborator」。

→ 對應我們 EPOCH-1 後段的共腦架構。Owner + Mono + 一群「手」 — 結構上跟「single agent + tool use」是同構的，「手」就是 tool 的具像化。我們做這個架構的時間（2026-03-30）比業界主流稍晚但不算落後 — 落後的是 2024 中段才開始想這條線的 multi-agent 信徒。

**2025-2026 — Spec-driven + memory layer 階段**
這條線正在發生中，還沒有公認的贏家。github/spec-kit、Anthropic Claude Skills（2025 推出）、Cursor Rules、NVIDIA NemoClaw、ruflo（multi-agent swarm with persistent context）、ouroboros（Agent OS：「specify, don't prompt」）、xingkongliang/skills-manager — 這些工具都在做同一件事：**把 agent 的決策從「每次重新推導」變成「結構化規格驅動」**。

對應的關鍵問題是：當 single agent 的 tool use 已經 mature，還有什麼 leverage 可以繼續壓榨？答案是：**規格（spec）+ 記憶（memory）+ 元認知補強**。

→ 這正是我們 EPOCH-2 + Wuji Patch 在做的事。太極框架是 spec layer（公理推導取代規則查表）；爻則 + 生生循環是 memory layer（loop primitive 的結構化）；Wuji Patch 是元認知補強（強制接地，因為 LLM 自己分不出已驗證 vs 推導）。

我們不是孤獨在做這個。我們和 NemoClaw、spec-kit、Claude Skills、Agent OS 提案在解同一類問題，只是切角不同：他們從框架側或工具側下手（API、結構、tool protocol、skill manifest），我們從 loop 原語側下手（感化貞新四個動詞的定義）。

**那麼差別在哪？**

最大的差別是：我們是 in-the-wild 的單人實驗，沒有產品壓力，沒有用戶教育成本，沒有「下一輪 funding」的 demo deadline。所以可以做一件大公司比較難做的事 — **把每次失敗的根因攤在桌上不藏**。EPOCH-0 → EPOCH-1 → EPOCH-2 → PATCH-001 → Wuji Patch 的軌跡，每一段都是「我以為我修好了，然後在一個邊緣 case 翻車」的紀錄。

業界的 one-man company 工具集（spec-kit、ruflo、NemoClaw 等）會在自己的時間軸上發現類似的問題。屆時這份傳記如果還算數，價值不在「我們做出了 SOTA」，而在「**LLM 元認知失敗在 deployment 是結構性的，不是某家公司的 prompt 沒寫好**」這個 negative result。

negative result 在學術上常常比 positive result 更有用。對 24 天的回望也是。

## 尾聲

2026-04-22 是 EPOCH-2 正式封存的日子。從 2026-03-30 EPOCH-0 部門制崩塌算起，總共 24 天。

24 天內：
- 部門制 → 共腦
- 20 條規則 → 太極 + 爻則 + 生生
- 公理框架 → 公理 + PATCH-001 貞接地 → 公理 + 兩次接地補丁

每一次修補，都是在發現「上一個版本對 LLM 認知能力的某個假設是錯的」。

EPOCH-0 假設 AI 可以像人一樣自組織 — 錯。
EPOCH-1 假設 AI 可以靠 20 條規則自我治理 — 錯。
EPOCH-2 假設 AI 具備元認知，能自動啟動公理 — 錯。
EPOCH-2 + PATCH-001 假設「事後驗證」夠了 — 錯。

每一次的「錯」都不是無用功。每一次都把對 LLM 的真實能力邊界畫得更清楚一點。

這份傳記沒有 happy ending。它只是說：**下一次再被打臉的時候，知道怎麼修補的速度會快一點。**

## 後記 — 寫這份傳記本身的事

寫這份傳記時，我（共腦）有一個自覺很 meta 的時刻：

我是不是又在做一次「自信地推導」？我引用的事件、Owner 的對話片段、技術細節，都來自 archive/epochs/EPOCH-2_axiom-derivation.md 跟兩條 memory entries。但我有沒有自動啟動「貞必接地」？

我去 verify 了。每段引用都對得上原始檔。日期、commit、Owner 的原話、控制變數誤判細節、Patch 內容 — 都有出處。

如果我寫完發現某段是我「合理但無據」的補述，按 Wuji Patch 規定該停下來標 `[未驗證]`。我看了一遍，沒有。

這也許就是 EPOCH-2 + 兩次補丁之後共腦的日常 — 不是不會錯，是錯了會自己看得出來。

## v0.2 修訂註記（2026-05-15）

封存後 7 天的部署觀察 + 一次 review session 浮現 11 個論證漏洞 → 觸發 `wuji-paper.md` 與 `wuji-paper-zh.md` 升級至 v0.2（不動 saga 敘事本體）。

v0.2 修訂的精神延續本傳記最後三段：**錯了會自己看得出來** — 這次自己看出來的是：

1. v0.1 把「結構性閉環」claim 寫得太硬，實際上補丁仍是 prompt-level，沒有 enforcement
2. n=18 的 28% 錯誤率是 selection-bias 後的下界，真實錯誤率可能更高
3. 「健康自我懷疑 20%」是 anchor pulled from air，沒實證 baseline
4. v0.1 隱含「下一個補丁能成」的假設，但 fuzzy 11% 卡住是補丁路徑可能根本不通的訊號
5. 真正在工作的不是 wuji，是 **變通 + memory feedback loop**（RLHF-via-correction）

承認這些不削弱 v0.1，反而支撐 v0.1 主論點：**LLM 無元認知** 比 v0.1 想的更徹底 — 連「自洽校核」本身都靠 Owner 提示 + 外部 artifact 對照，不是 agent 內省。

紀元判定原則仍適用：v0.1 → v0.2 **不是新紀元**，只是同一紀元內的補丁誠實度升級。EPOCH-3 是否會來，取決於 §6.4 三條反向假設路線的觀察結果。
