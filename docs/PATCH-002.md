# PATCH-002：化的接地修正（Wuji Patch）

> 版本：v0.2 → v0.3
> 日期：2026-04-22
> 嚴重度：重大 — 與 PATCH-001 對稱補完

---

## 發現了什麼問題

PATCH-001 修了「貞」（校驗）的接地，但問題沒消失。AI 仍會從未驗證的前提出發，**動手執行**之後才發現前提錯。

實際案例：在生生循環中，AI 收到一段描述就直接進入「化」（轉化、執行），到了「貞」階段才被 PATCH-001 攔下。但這時已經寫了一堆程式碼、做了一輪推導 — 沉沒成本已產生，重來成本高。

換句話說：PATCH-001 是**事後攔截**，不是**事前阻止**。

## 為什麼會這樣

生生循環有兩個行動點：**化**（執行）和 **貞**（校驗）。PATCH-001 只在「貞」加了接地關卡，「化」仍是無條件啟動。

這違反對稱性 — 既然「貞」需要接地，「化」也應該需要接地。否則 AI 在「化」階段可以從幻想前提出發，把整套錯誤推導跑完，等「貞」才停下來。浪費的是計算、token、人時。

LLM 在「化」的時候不知道自己的前提是否已驗證。框架必須**結構性**強制檢查，不能假設 AI 會自我啟動。

## 怎麼修

加一條與 PATCH-001 平行對稱的規則 — 化也必須接地。

### 改動：化 = 接地，不是直接執行

舊版（PATCH-001 後）：
```
感 → 化 → 貞 → 新
貞而無據，標記不確定，交人。
貞必接地 — 比對外部事實（原始碼、文件、數據），不是比對自己的推導。
不生即死。
```

新版（PATCH-002 後）：
```
感 → 化 → 貞 → 新
化必有據 — 前提未接地不動手。技術前提必須指向原始碼、規格、測量值；無出處則標 [未驗證] 停下查證。
貞而無據，標記不確定，交人。
貞必接地 — 比對外部事實（原始碼、文件、數據），不是比對自己的推導。
不生即死。
```

## 設計邏輯

PATCH-001 的 `貞必接地` 與 PATCH-002 的 `化必有據` 平行對稱：

- **化必有據**：行動前接地（fail-fast，省成本）
- **貞必接地**：校驗時接地（last-line defense）

兩個行動點（化 + 貞）都有接地要求 → 形成閉環。任何一端被繞過，另一端會接住。

## 怎麼更新

1. 重新複製 `templates/CLAUDE.md` 覆蓋你的舊版
2. 把你的「我的卦」（兩儀、四象、應用層太極）貼回去
3. 完成

「我的卦」是你個人校準的結果，框架更新不影響它。
